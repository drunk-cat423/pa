# 本人私聊中的 Codex 任务

设置 `PA_CODEX_SOCKET=/run/pa-codex/worker.sock` 后，PA从 `policy.json` 的 `ownerBindings` 中选出唯一已接入的QQ本人私聊。该绑定必须满足QQ私聊的roomId与真实senderId相同。缺失或多个候选时拒绝启用，不能用昵称或跨平台人物绑定授予代码执行权限。其他群聊和私聊的Pi会话不注册委派工具。

本人可以说“查一下日报为什么没发，只读排查”，或“把这个bug修一下，跑针对性测试，先把改动给我审查”。模型在正常准备阶段后调用 `delegate_task`，`read`只读调查，`fix`允许在独立工作目录修改。工具入队成功后程序返回任务编号与短确认，普通聊天随即继续。任务目标只包含当前明确要求及必要背景，研究报告、画像和聊天全文不传给执行器。

后台执行器通过本机Unix socket运行，模型固定 `gpt-6.1-sol`、`high`，单任务512MiB。执行器负责实际任务队列、Git工作目录、Codex会话及命令记录。PA只负责可信来源、身份和QQ投递；执行器的具体安装与隔离规则见部署说明。

任务完成后 PA 在本人私聊发一条文字，说明任务是否完成、改了什么、实际验证到什么效果或遇到什么阻塞。代码差异和命令记录保存在执行器中供核对。模型的“已测试”自述不能替代命令记录。回复“任务编号那个修复，撤掉文案改动”，模型调用 `continue_coding_task` 续接同一工作目录和会话；省略编号仅在现有任务唯一时可以续办。`coding_status`查看准确状态，`send_coding_result`按本人要求重发已有文字结果。

PA使用独立 `codex-delivery.sqlite` 记录来源消息的幂等请求和每版本通知。后台每两秒只检查未完成的来源请求，完成通知后停止查询该请求。POST超时不自动重提任务，通过worker的requestId查询恢复已接受结果。通知先持久写入sending再发QQ，重启时未知sending转uncertain，未知发送不会自动重发；本人可在新消息明确要求重新领取。

执行器明确返回4xx拒绝时（408除外）立即结束该来源请求的等待。未知接单只查询，不重提；同一requestId连续三次成功查询均不存在时结束自动恢复，原始请求与未确认状态仍留存。每轮最多查询20条、按上次检查时间轮转，并有8秒批次预算；单条查询失败继续处理其他请求，避免旧失败挡住后续结果。账本保存真实渠道owner的哈希，策略切换后仅查询当前owner的来源；旧版缺少owner的预览请求保留审计并结束自动投递，不推断收件人。

离线验收入口为 `test/codex-service.test.mjs`，覆盖真实本机HTTP socket接单、文字回报、同任务续办、私聊身份边界、未知投递恢复，以及本地SSE驱动的Pi实际工具调用。生产验收需要本人在QQ发起任务，再核对worker的模型、工作目录、命令与内存记录。
