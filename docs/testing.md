# 测试保留规则

当前保留76个用例、41个测试文件，清理前为223个用例、57个文件。产品源码、依赖和生产配置未因清理而改变。

保留依据逐项写在 [test/regressions.json](../test/regressions.json)，分成三个明确来源：

- `incident`：已有具体产品故障或独立复现，例如身份串人、缓存骤降、提案失败堵住整理、日报整篇失败、报告正文丢失。
- `user_issue`：针对用户明确提出的问题，例如85%容量触发、只发送本轮图片、普通纠正不另建区域、原话限制及研究/提醒承接。
- `critical`：少量不能由已有端到端用例替代的检查，须写清会导致的越权、原文丢失、重复收费或重复投递后果。不能只写“重要功能”。

已删除旧Pi文件审计矩阵、旧分页/退役计数机制测试、古早迁移组合、大量参数边界与基础成功路径，以及已有更完整故障回放覆盖的底层重复检查。旧测试仍可从Git历史追溯，不留跳过项或另藏一套“大测试”。

新增功能默认先做可观察的实际验收；不要自动增加整组单元测试。出现真实故障或用户明确指出问题后，优先在同一入口留下最小回归。若不得不新增关键检查，需要在登记中解释独立风险和现有用例为何不能覆盖。

```powershell
node scripts/repo-check.mjs --list
node scripts/repo-check.mjs cache
node scripts/repo-check.mjs --changed src/runtime.ts --list
node scripts/repo-check.mjs all
```

所有scope只指向保留下来的实际文件。源码变更仍选择相关回归，并包含本次新增或修改的测试；共享测试辅助文件变化和未知源码模块选择全部现存回归。发布验收不会为凑数量恢复已删除用例。

这些用例使用临时SQLite、本地HTTP或受控替身，不调用收费模型、不接QQ或生产库。通过并不代表所有功能和边界都覆盖，也不证明实际模型的语义判断一定正确。
