# QQ 长回答与 Markdown 分页

使用 QQ 官方 Bot 的原生 Markdown 和自定义指令按钮，不依赖 NapCat、QQ 客户端或外部网页。

## 阅读方式

短回答直接展示。长回答先发简短摘要及正文入口，正文按固定边界分页。摘要是第 0 页，正文从第 1 页开始；上一页可以返回摘要，最后一页不提供越界的下一页按钮。

每条分页消息带回答标识和页码。按钮编码明确的回答标识与目标页，不维护整个群共用的“当前页”。多个人同时翻页、翻阅旧回答时，各条消息的按钮仍指向原回答和指定页。

翻页会在聊天中发送一条新消息，不会修改原来的消息，也不会打开独立的全文阅读窗口。可复制文字与代码。页码与展示边界由程序控制，模型不负责计算页数或按钮指令。

点击按钮触发已有指令通路，由 harness 读取持久化页面并发送，不调用模型、不重新搜索或归纳。只能读取当前渠道账号、房间内已经发布的回答；群内成员可以阅读本群回答，不能借按钮取得其他群或私聊的内容。

## 摘要、正文与投递

摘要使用同一次模型回答开头的简短结论，不增加一次摘要模型请求。模型未按要求给出独立结论时，程序只能作有界预览，不把截取内容冒充额外生成的事实。

完整 Markdown 原文、固定页面和摘要先持久化，再发送摘要与阅读入口。只有入口确认送达，完整回答才作为已发布内容进入上下文。正文可通过按钮按需获取，并不要求用户读完所有页后才记住这次回答。入口发送失败或结果未知时，不把仅生成的正文当作已经发布；未知投递不自动重发。

正文分页按 UTF-8 字节留出平台消息空间，并尽量保留段落和代码围栏的可读性。原始完整回答独立保存，不因分页改变或截断。进度提示与分页发送继续经过当前房间的发送队列；QQ 的被动回复窗口和次数限制仍适用。

`/result` 领取已发布的长回答时复用原文档摘要与按钮。若首次摘要投递未确认，本人可显式 `/result` 重新领取完整展示正文，创建新的摘要入口；这不会修改旧未知投递，也不会重新调用模型。沿用管理查询的记录语义，领取操作与其回复不作为新的普通聊天轮次参与压缩。

## 引用

发送成功后保存实际显示的摘要或页面正文，并关联回答、页码、QQ 消息 ID 和平台返回的引用索引。引用第 2 页时，提供第 2 页的实际内容；引用摘要时，提供摘要。消息 ID 与引用索引是不同类型，均只能在当前会话内解析。

QQ 若直接回传内联引用文字，沿用当前引用入口；只回传引用索引时，使用本地映射定位。引用未知、未确认投递或其他房间的消息时，不按昵称、相似正文或页码猜测。

2026-10-18 已在现有测试群实测：用户可以引用原生 Markdown＋按钮消息；事件带 `ref_msg_idx` 和原始 Markdown 正文，不包含按钮配置。该项证明平台能力及既有引用接收通路，分页导航本身仍需要随实现验证。

## 对上下文和压缩的影响

完整回答在 `messages.text` 保留一次原始 Markdown。摘要入口确认送达后，沿用已确认回复进入可见消息序列的机制；上一页、下一页和重复读取是同一篇回答的展示，不产生新的 AI 正文记录。

历史与后台整理读取的仍是结构化文本记录：消息 ID、角色、发送者／回复对象、正文与顺序。Markdown 的标题、列表和代码围栏保留在 `text` 中。`keyboard` JSON、按钮指令、页码展示和重复页面不会混入正文，也不会因翻阅次数增加而重复占用上下文。

翻页控制指令保留在操作记录中，但不作为普通聊天或画像事实参与整理。85% 容量触发、实际 token 校准、固定压缩快照、`continuationSummary` 和 Topic 检索保持原有规则；压缩处理完整回答，而非只处理用户最近打开的一页。

## 平台证据与边界

2026-10-18 在当前允许的测试群内完成文件、原生 Markdown 和 Markdown＋自定义指令按钮的主动／被动接口探测；接口返回成功消息 ID，用户确认第一轮 Markdown、文件和按钮显示正常。普通文本附带按钮虽然被接口接受，客户端未显示，因此阅读按钮只与 Markdown 一起发送。

先前按钮探测使用 `enter=false`，仅填入指令。正式分页使用指令按钮自动发送目标页指令；不能将先前探测当成自动翻页端到端验收。私聊权限、回调按钮 ACK、PDF 预览和平台文件上限不在上述测试结论内。

- [官方按钮定义](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/trans/msg-btn.md)：指令按钮、`enter`、权限和回调类型。
- [官方 SDK 引用字段](https://github.com/tencent-connect/qqbot-nodejs/blob/main/src/protocol/types.ts)：发送回执的 `ext_info.ref_idx`。
- [官方 SDK 入站引用说明](https://github.com/tencent-connect/qqbot-nodejs/blob/main/src/protocol/gateway/event-dispatcher.ts)：`refMsgIdx` 与内联 `msg_elements`。
