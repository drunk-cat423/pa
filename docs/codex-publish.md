# 在本人私聊确认发布

设置 `PA_PUBLISH_SOCKET` 后，本人先收到一项 Codex 修复的完成报告，然后直接发送 `把这版上线`，或 `把任务 <任务编号> 第 2 版上线`。程序从真实 QQ 私聊消息读取确认，不提供由模型调用的发布工具。引用、图片、其他人的消息或包含这句话的讨论不能授权发布。

省略编号时，使用最近一次已经确认送达的任务报告。任务必须是成功完成的 fix，当前任务版本及保存的 Git diff 哈希必须与所报告的版本一致。任务已经续办、失败、只读或没有代码变动时，需要先取得可发布的完成报告。任务结果与发布结果分开通知。

确认后先向独立发布程序提交 prepared 记录，PA 回复发布编号对应的任务和版本。只有 QQ 确认接收该条回复后才调用 start。发布不依赖 PA 的进程寿命。启动响应中断时通过同一 requestId 续查或幂等启动，原确认未能确认送达时不启动。

初次确认回复状态未知时，新的本人原始确认复用原来冻结的 requestId 和补丁哈希，再确认回复送达后启动。`查看发布结果` 只读取本人最近发布的独立记录，适用于自动通知未能确认送达的情况。

PA 的 `codex-publication.sqlite` 保存已报告版本、来源请求、明确送达的确认和通知状态。发布成功、失败或回滚后，新版或回滚后的 PA 在 QQ READY 后查询外部发布结果，再向原本人私聊发送短说明。通知先写 sending，再发送，未知发送在重启后标为 uncertain，避免重复。发布过程的原始错误和 Git 信息保存在独立发布服务中。

回滚必须保留这个发布通知账本。发布前的数据库快照应在确认和启动已落盘后创建。测试覆盖原始确认及身份边界、未确认回复不启动、版本变化拒绝、服务重启后成功与回滚结果各通知一次。

## 发布检查期间的 QQ 接入

部署同时配置 `PA_PUBLISH_GATE_FILE` 和 `PA_PUBLISH_INBOX`。门禁文件由 root 写入，值为 `hold` 时，新版 PA 连接 QQ 并打开房间、检查 SQLite 业务会话可用性、初始化业务存储，成功后报告 `publish_standby_ready`。值为 `activate` 时再次核验并报告 `publish_activation_ready`。值为 `opening` 时完成正常服务启动，调度器和自动记忆仍受独立运行门禁约束，成功后报告 `publish_open_ready`。任何门禁阶段均不发送 QQ 消息、不发起模型工作，QQ 断连时只报告等待连接。发布最终决定持久化且门禁删除后才允许执行和输入重放。

所有已允许路由的真实 QQ 消息在启动及门禁期间，先同步写入 `PA_PUBLISH_INBOX/inbox.sqlite`。该目录由 pa 持有、权限 0700，位于应用快照目录之外，回滚恢复应用数据不会覆盖它。删除门禁后才启用业务执行，并按每个房间的原始顺序把收件箱消息交给正常持久入队。只有入队、观察入库或确认重复后才删除条目。某房间接纳失败时，原文保留，该房间至少间隔 30 秒重试，其他房间继续接入；路由撤销后的原文也保留供本机维护。真正的收件箱存储或持久化异常会停止服务。重放已入队消息利用原 QQ eventId 去重。

普通安装不配置这两个参数时保持既有接入方式。配置后，启动阶段通过外部收件箱保护输入；QQ READY、完整初始化及收件箱清空后，普通消息直接走原有接入路径。发布门禁存在或有待重放消息时，才继续使用外部收件箱。

## 对应补丁的测试验收

发布构建会复用 repo-check 的分组，按源码路径选择已有相关回归，并合入本次新增或修改的测试文件；未知源码模块选择全部回归。测试选择脚本和候选测试均在无凭证的构建账号内运行。源码改动没有可用测试时拒绝发布，不接受模型自行声称通过。

独立发布任务目录的 validation.json 保存候选 commit、冻结 patchSha256、测试文件、验收命令和实际退出码。只有与该补丁匹配的 passed 记录才能复用候选版本；失败停止发布，成功通知说明验收文件数。普通诊断命令的非零退出不自动等于验收失败。安装发布器时须同时更新 root 持有的 publish-release.mjs；普通候选修改不能自行改发布器。
