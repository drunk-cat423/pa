# PA 工作台账设计

状态：可实施设计，尚未接入生产聊天工具。2026-10-26。

## 要解决的事情

用户说“周五前比较这两个产品”时，需要一项可查询、有截止时间、有产物、能主动告知进展的工作；聊天摘要中的一句承诺不能承担执行职责。

台账记录“答应做什么、做到哪一步、下一步何时执行”，不取代聊天记录、人物画像或研究材料。现有研究任务继续使用自己的资料、预算、检查点和报告；台账只连接这些执行器。第一版支持研究与定时提醒两种类型，不开放任意 shell、文件系统或自动联系第三方。

## 用户看到的流程

1. 用户明确交代工作。模型提交目标、产物、完成标准及必要时间信息；harness 校验实际用户、授权能力、参数和预算。
2. 同一个事务保存工作、首次唤醒及操作回执。成功后才确认“已安排”；日期或范围不清楚时只澄清，不制造已经安排的承诺。
3. 到时由程序唤醒。先查是否已取消、是否仍有授权、是否在静默时段、是否有预算，再调用对应执行器。有现成结果或单纯提醒时不调用模型。
4. 有实质进展才通知：完成、需要用户补充、发生失败或临近明确期限。没有变化不发消息，也不为了“看看有没有变化”反复调用模型。
5. 用户可查询本人台账、补充要求、取消后续执行。修改使用版本号；新增要求必须保存后才能生效。

## 数据及职责

| 对象 | 必须保存 | 为什么分开 |
| --- | --- | --- |
| work_items | id、owner_person_id、kind、goal、deliverable、completion_criteria、origin_message_id、来源 route、status、version、deadline_at、timezone、next_wake_at、blocked_reason、created/updated_at | 当前可查询的工作事实，不包含全部材料 |
| work_authorizations | work_id、绑定/策略版本、允许执行器与动作、通知对象、总预算、截止或撤销时间 | 模型不能自行扩大权限；执行时重新核验 |
| work_attempts | work_id、attempt、执行器引用、状态、lease_token、开始/结束时间、未知调用标志、用量、错误 | 单次执行可审计，过期租约不等于可重跑 |
| work_events | work_id、seq、event_type、request_id、时间、简短原因及来源引用 | 追加记录，幂等和版本变更证据 |
| work_notifications | work_id、event_seq、接收 route、通知内容/产物引用、状态、静默延期时间 | 工作完成与消息是否送达独立，避免发送慢拖住计算 |

对状态、时间、索引字段使用结构化列；只有执行器专属小参数使用有大小限制的 JSON。不能把整个聊天、报告或模型上下文存进 work_items。原始材料仍在现有研究存储，画像仍在原模块。

第一版每个研究任务最多连接一个 work_item，`UNIQUE(kind, executor_ref)` 防重复。创建台账及现有 research_tasks 必须共用同一 SQLite 事务；禁止先创建研究再另开事务添加台账。现有研究先按需建立关联，不把所有历史任务重新执行一遍。

## 状态和完成条件

| 当前状态 | 允许后继 | 触发条件 |
| --- | --- | --- |
| scheduled | running / waiting_user / cancelled | 到达唤醒时间且校验通过；缺少授权需确认；用户取消 |
| running | completed / scheduled / waiting_user / waiting_external / failed / interrupted / cancel_requested | 执行器保存结果；有已授权下一步；缺输入；外部操作处理中；明确失败；结果未知；用户要求停止 |
| waiting_user | scheduled / cancelled | 本人补充要求并保存；取消 |
| waiting_external | scheduled / completed / failed / interrupted / cancelled | 只读查询取得确定外部状态；未知结果不得自动重新提交 |
| cancel_requested | cancelled / completed / interrupted | 能确认停止；取消之前已完成；无法确认已发出的外部动作 |
| interrupted | scheduled / cancelled | 用户明确批准继续，或只读核对证明可安全恢复 |
| failed | scheduled / cancelled | 明确的新续作请求；不因定时器自动重试收费调用 |
| completed | scheduled | 只有本人明确追加要求才能递增 work.version 并创建新 attempt；旧 attempt 终态不变，旧结果保留到新结果持久化 |
| cancelled | 保持终态 | 不隐式重新开启；确实要恢复目标时，由本人明确创建新工作并关联旧编号 |

`completed` 需要程序可验证的完成凭据：研究执行器已保存正式报告及结果状态、提醒内容已生成并建立通知项。提醒“已安排”“通知生成”“对方确实收到”是不同事实；投递状态单独显示。研究 `partial/blocked` 不得映射成 completed；未解决缺口应在台账呈现，不能靠模型声称完成。

期限和唤醒也不同：`deadline_at` 是用户期待完成时间；`next_wake_at` 是下一次检查时间。全库用 UTC 毫秒，原始时区单独保存，聊天按北京时间显示。明确的一次性时间优先，首版不支持任意 cron 或模糊循环指令。过期提醒只合并为一次，并标注迟到；不补发每个错过的时间点。

## 调度、预算与崩溃恢复

- 只扫描 `(status='scheduled', next_wake_at)` 的部分索引，`ORDER BY next_wake_at,id LIMIT N`，不扫描聊天和材料。启动只恢复未结束 attempt 与到期项。
- 领取通过短 `BEGIN IMMEDIATE` 事务：校验版本和取消状态、写 attempt/lease_token、置 running、记事件后提交。外部调用始终在事务外，不能把 SQLite 写锁持有几分钟。
- 同一工作只能有一个 active attempt；全局和按 owner 的并发上限由 harness 控制。候选窗口内公平轮转，另有按 owner 的索引查找，防止一个 owner 的大量早到任务饿死其他 owner。聊天优先，后台使用独立低并发执行槽。
- 真正请求之前，在同事务中预约预算并标记 dispatching。崩溃在“预约后、请求前”也按未知结果保守处理，不能因看不见响应而自动重发收费请求。
- 结果提交必须同时匹配 work.version、attempt、lease_token；迟到 worker 只能留下审计，不能覆盖新版本、取消结果或产生新通知。预算记账按 request_id 唯一，不能因迟到回执漏计实际已发生用量。
- 纯本地、可幂等的投影计算可恢复；模型/搜索/外部写入未知状态进入 interrupted，保留输入和检查点。租约过期仅表示 worker 失联，不是重试授权。
- 对于现有研究任务，台账按执行器的 attempt/checkpoint 读取状态，不新建第二份研究循环，不重置其16次模型/24工具/6搜索预算。台账级总预算在研究预算外再收紧，不能放宽。
- 每次只读数据库查到期是程序成本；没有到期工作不构造提示词、不调用模型。唤醒由最近 next_wake_at 安排单个计时器，并设有上限的低频校准以发现其他进程的新工作。

## 通知与权限

通知产生与状态变更同事务，唯一键 `(work_id,event_seq,recipient)`。发送前保存 sending；明确成功才标 sent。连接中断或服务重启使未知发送变 uncertain，不自动重发。用户可以主动查询结果。发送队列与计算队列分开，复用此次按房间限流的 transport 层。

默认通知原任务来源场景；跨私聊/群转发必须有明确授权，不因 owner 画像跨场景共享而共享任务内容。个人台账只允许本人按真实 person_id 操作；群友不能通过提供 owner 字段代操作。群共同任务需要独立产品权限设计，不纳入首版。

每次唤醒重新解析实际绑定和当前策略。身份解绑、授权撤销、通知房间不再允许接入时进入 waiting_user；不得换一个可用房间“试着发”。静默时段延迟普通通知，不能由模型自行突破；默认不设置需要突破静默的紧急通道。

## 与提示词、画像、清理的关系

对话固定提示词只说明可用台账工具与已保存回执规则。当前问题相关的任务摘要后置，最多携带少量目标、状态、期限、下一步和产物引用，不把全部台账加入每轮上下文。创建和续作仍经过现有 prepare_turn 及工具授权，不另加必调模型。

执行器只接收该任务目标、已保存新增要求、必要材料/检查点和本次允许工具；不默认携带群友画像、群聊天或其他任务资料。固定执行规则在前，变化内容在后，保持前缀缓存。

台账不能成为报告的第二份永久副本。研究正文、日志和 Pi 会话仍遵守现有30天清理，台账仅保留目标、状态、摘要、失败原因、用量、事件及已过期产物标记。过期引用明确不可读，不能触发自动重跑。新台账必须登记独立保留契约；不趁这次设计修改生产清理范围。

## 实施顺序和验收

1. 增加台账/attempt/event/notification 存储及事务API，完成幂等、并发CAS、取消与崩溃测试，不接模型。
2. 连接现有 research_tasks 的创建、继续、完成与失败事件，保留原执行器；聊天工具只访问本人。先对测试任务启用，不回填并重跑历史工作。
3. 加入一次性提醒执行器与持久唤醒；检测“已安排”必须有真实回执。没有明确时间不创建计时器。
4. 共享当前按房间输出约束；上线前验证权限撤销、静默延期、未知投递、报告过期、重启漏发与重复唤醒。

离线原型重点验证100,000项历史记录下到期查询是否命中索引、每批读取是否有界、双连接不能重复领取、旧token不能提交、取消不丢审计、未知请求不自动排回。测量是本机合成数据结果，不代表服务器吞吐或模型答复质量。

## 设计自审与取舍

没有采用“万能自主 agent 循环”：它会把无变化检查也变成模型费用，增加未知请求和权限问题。采用有限工作类型和确定性调度，先把真实承诺做好。

没有重造研究状态机：研究已有的材料/预算/检查点继续是唯一执行事实，台账保存入口与结果引用。双系统状态漂移通过同库事务与可重放的本地事件投影解决，不能用第二个定时模型判断研究是否完成。

租约不解决外部恰好一次执行；未知请求保持 interrupted，付出少量人工确认换取不重复计费。未来供应商有可靠幂等键时，才能按具体执行器开放更积极的恢复。

初始限制是单机SQLite、多worker短事务、有限任务类型，不设计分布式锁或消息中间件。若实测写锁等待影响前台，再根据日志拆服务；不能仅凭未来可能扩张就先引入基础设施。

## 离线验证结果

本机100,000条合成台账、10条到期工作、每次最多读取8条：到期索引查询中位数约0.007ms、p95约0.009ms；相同查询禁用索引中位数约7.33ms。EXPLAIN确认命中到期部分索引，无临时排序；按owner领取也命中独立复合索引。

双连接原型通过：原子领取不重复、写锁互斥、未知请求不自动重试、取消版本栅栏、迟到用量仍保存、状态/事件/通知同事务回滚、通知唯一键去重、未知发送不自动重发。原型只验证这些数据库机制，没有实现研究执行器接线、聊天权限工具或生产定时任务。

独立只读架构审查指出 completed“终态”与续作的歧义，已明确为旧attempt终态不变、work_item经本人显式续作递增版本再进入scheduled；cancelled不能隐式复活。当前结论是方案在单机SQLite范围内可实施，不需要新增基础设施；上述实施顺序是后续开发边界，本次没有开启新的主动任务能力。
