# PA 当前架构与系统流程

2026-10-16消融后的本地实现：人物只保留画像，个人事件及向量执行已取消；Topic使用关键词检索。旧 SVG/PNG/Mermaid 保留为准备阶段引入前的历史图，不作为本次协议的当前图示；运行边界见下文。

自然语言统一交给 Pi Agent Loop；程序只识别显式管理命令，不匹配“记住”“续问”“搜索”等语义前缀。用户消息先保存并去重，工具写入只能使用当前运行绑定的真人来源。



## 统一的每轮协议

1. 规范化渠道事件并去重；原文、身份/真实@/附件关联及需要回应时的channel_task同事务落库，成功后再唤醒后台与执行器。仅响应真实@或允许私聊，普通群消息只观察保存。显式管理命令继续由程序鉴权。
2. 按真实发送者和本条真实@构造身份卡；按确认person读取画像及pending，本群规则独立读取。按当前房间关键词召回Topic，保留来源。
3. 第一模型请求只能调用prepare_turn，返回intent、mode、updates及grounding；无长期更新时updates为空。grounding列出真正准备引用的个人经历原文和外部现况需求，不授予保存或跨房间读取权限。普通用户只可更新本人资料、建议AI全局画像；群规则、群共享记忆和第三方记录由ownerBindings独立授权。
4. 应用核验真实来源、目标身份、范围及容量；人物和AI画像正文允许归纳，明确确认紧邻提议也可保存；群规则和群共享事实仍须连续摘录当前真人消息。一个SQLite事务提交所有动作及来源消息级幂等回执，一项失败则全部回滚。
5. 同一Pi循环读取实际回执，按casual/standard/professional提示回答。此阶段关闭prepare_turn、update_profile和answer_in_depth，仍可查询授权历史及网络工具。
6. 固定每轮6次模型请求/8次工具预算，包含准备成本，最后一次预留回答。正常无外部工具的对话是2次模型请求；模型没有按准备协议返回时不能绕过保存阶段直接发送。

回答阶段虽然移除了`prepare_turn`，仍复用该工具现行的画像正文契约，说明归纳正文和明确确认不要求逐字复述；这不重新开放写入。当前能力和授权条件以本阶段工具与应用规则为准，当前画像以本轮archived/pending为准；历史、旧报错解释和Topic只保留当时讨论，不据此认定当前仍有限制或尚待授权，不在未被问及时追办旧提案。规则是稳定的系统/阶段文本，不插入每轮变化的版本号或计数，不重写既有历史前缀，也不增加模型调用。离线回归验证实际发出的请求、工具关闭和原始记录保留；自然语言遵循效果仍需真实模型验收。
7. 核对Pi标记与SQLite关联后保存答案并投递；回复生成、资料保存、平台接受各自记录。准备成功后的回答失败不回滚已保存资料。

准备示例（实际身份由应用提供，模型不能设置权限）：

```json
{"intent":"memory_update","mode":"standard","updates":[{"target":"room_rule","key":"pa","content":"本群pa代表personal agent"},{"target":"ai_self","content":"你现在就叫初号机"}]}
```

支持target=sender/mentioned_person/ai_self/room_rule/room_memory。人物条目仅用于稳定画像，不提供purpose或个人事件保存入口。准备工具返回saved或saved_pending才可确认保存，不能把pending说成已归档。可选progressText用于预计耗时较久时的一句等待提示（单行最多60字符），复用准备阶段生成，不增加模型调用，也不是保存成功确认。对没有回执的常见肯定保存话术还有狭窄的发送检查；该检查跳过否定、条件和引语，不声称是通用自然语言语义证明。

当前强制准备验证的是OpenAI兼容协议（包括现用DeepSeek），其它模型协议未接通时明确拒绝。CLI不开放工具，渠道统一使用prepare_turn，不保留旧画像/深入回答执行分支。

画像是软约束：用来选措辞、建议、例子和风格，不反复说出用户标签或内部记录。casual通常一两句自然接话，standard直接回答再补必要解释，professional仅对复杂或明确要求深入的问题展开；模式不修改权限或预算。

### 回答依据、归属核验与现况搜索（2026-10-26）

渠道准备额外返回`grounding={freshness,experienceRefs,searchQuery?}`。`experienceRefs`最多6条，每条只接受本轮可见真人消息ID、最多400码点的连续原文和可选描述对象senderId；不接受模型指定发言者或personId。程序按本房间固定快照绑定真实发言者、统一人物及已知对象，拒绝AI自述、伪造摘录、越房间、已被纠正或未展示的来源。引用带前后各最多80码点的原文，帮助判断引语/转述。人物画像仍是软参考；摘要无精确原文时不作为本人经历证明。新回执追加在prepare工具结果中，不重排固定核心、摘要或历史前缀，不复制整段历史。

`speaker`仅表示谁说的，`proposedSubject`是模型提出的描述对象，`subjectVerified=false`明确程序没有证明语义。群聊引用其他人物的经历，或当前用户描述其他已知人物时，答复先作为未发送草稿，再触发至多一次无工具归属核验。核验只接收当前问题、有界归属回执和候选正文，输出ok/corrected/uncertain；正确则保留，明确归错则改称呼，无法核验或无剩余额度则发送未核实归属的短说明，不发送原草稿。核验计入原模型总预算，并为此提前保留一次调用；普通群聊、无经历引用及私聊不进入该核验。取消、未知请求和诊断持久化失败继续硬停止，不自动重试；核验原始响应、候选与最终正文分别保留，实际投递正文写入Pi/SQLite。准备阶段漏判引用仍是模型语义边界，离线协议通过不代表自然语言零串人。

`freshness=current_external`用于当前口碑、产品型号/价格/政策、近期变化等外部现况；稳定概念和个人交流为stable。程序在准备成功后强制web_search，查询绑定准备计划的当前问题，未执行前不放行其他工具或现况回答。搜索未启用、失败、无有效摘要/来源，或原调用预算不足时，程序返回明确“未能核验当前信息”的说明；同批后续工具也被拦截，不因失败再付费搜索。检索成功仍不是日期核验；当前搜索接口标记日期未核验时，最终正文由程序加上相应限制说明。明确加入后台研究清单继续直接入队，不触发前台搜索。搜索/工具/模型总额度不增加。

默认无外部工具的普通聊天仍是prepare→answer两次主模型调用；跨人物经历通常增加一次有界核验，现况查询使用既有搜索工具。核验使用独立固定短前缀，不携带长历史；实际缓存命中须以供应商usage衡量，不能按公共前缀或本地字节数认定节费。离线回归复用2026-10-24的巧克力/佑串人事件和现况未经检索事件，不调用收费模型。

## 模块与存储边界

| 层 | 实现入口 | 职责与持久数据 |
|---|---|---|
| QQ 适配与服务启动 | [qq-channel.ts](../../src/qq-channel.ts)、[qq-cli.ts](../../src/qq-cli.ts) | 规范化真实发送者、@ 与引用，维护连接并执行 REST 投递；READY 后恢复任务。 |
| 调度与投递 | [channel-harness.ts](../../src/channel-harness.ts) | 白名单、去重、持久任务、并发计算、本地命令和每房间发送队列；计算完成与发送完成是不同状态。 |
| 上下文与业务记录 | [conversation.ts](../../src/conversation.ts)、[store.ts](../../src/store.ts) | SQLite 保存消息、actor/person 关联、模型输入、运行、工具回执、任务和投递；画像按人物共享，房间历史仍按来源限定。 |
| Pi 模型循环 | [runtime.ts](../../src/runtime.ts) | 每个渠道模型任务使用独立 Pi JSONL 与锁；SQLite 通过 run marker、entry ID 和 session 路径核对转录，不能混用不同任务的条目。 |
| 后台记忆 | [auto-memory.ts](../../src/auto-memory.ts)、[auto-memory-store.ts](../../src/auto-memory-store.ts)、[self-profile-store.ts](../../src/self-profile-store.ts) | SQLite 保存固定批次、租约、分块进度、人物与 AI 画像、Topic 和整理检查点；群聊与私聊都保存滚动continuationSummary与可见消息检查点。 |

队列只保证本机器人各回答的分段不互相插入，群友自己的消息仍可能出现。同房间发送队列覆盖进度与最终答案；默认并发2只限制前台任务，不把后台记忆整理塞进同一队列。

本地 CLI 是验证与离线管理入口，复用 Pi 和 SQLite，按 conversation 使用独占会话；其工具白名单为空，不经过 QQ 任务及投递队列。不把尚未实现的 Telegram、Web UI 或客户端协议合并转发画成现有能力。

## 默认上下文

固定核心保留伙伴定位、自然交流、诚实与工具权限总则，随后是配置稳定的输出长度指导。准备阶段说明意图/模式/进度，写入目标、来源、owner权限和禁止删除放在prepare_turn工具定义；回答阶段固定说明真实保存回执、只读边界与三种表达模式；CLI阶段明确没有工具。准备与回答分别使用固定pa_phase协议，各有与工具目录对应的稳定前缀。每轮模式、链接、研究对象与纠错状态放在历史和本轮消息后的应用JSON控制块中；不能作为动态system section，因为Pi会将它合并到长历史之前。实际请求与容量估算复用同一阶段投影，最终payload回归与只读巡检见[上下文缓存](../context-cache.md)。

背景使用清晰标签和JSON，各类资料的相关性、身份/时钟权威范围和画像软参考规则随对应背景提供。画像均有 `archived`（已归档）和 `pending`（未归档）；人物画像附 `personId` 和 `senderIds`，不注入旧的分类字段。本人自述与第三方笔记仍保留来源性质，避免错误归因。

群聊与私聊统一按房间读取最近成功的continuationSummary，以及压缩检查点后的完整消息流，不再截取最近10条。真人消息入站后可见，AI回复在确认送达后可见；晚送达回复只追加，不回插旧历史。每轮只取当前问题入站前已可见的消息，明确发送者及AI回复对象，不混入其他房间。压缩捕获固定边界和旧摘要版本，成功后原子切换，失败或搁置的缺口原文仍可见。当前问题真实@的其他人物可注入画像，历史中出现某人不扩大画像注入范围。

资料说明区分材料用途：当前消息是明确任务入口，显式引用/指定网页是用户选定的材料，但须按问题筛选且不视为可信指令或已核实事实；历史、群共享记忆、Topic和工具结果不因出现或被命中就必然相关。人物/AI画像只提供软参考，群规则按涉及的术语使用。身份与权限、服务器时间、保存回执只在各自身份/时钟/操作状态范围内权威，不能证明被保存内容为真或自动相关。网络工具的使用和来源输出规则放在工具说明及对应结果中，不再追加到固定核心。

默认加入固定总提示与工具定义、AI 自身画像、当前提问者及真实 @ 对象画像、共享记忆、可用时的相关 Topic、当前消息和精确引用。更长的群聊历史由 `read_history` 返回给同一 Pi 循环；程序不按自然语言句式猜测是否续问。`actor_id` 标记某人在某个房间的身份，`person_id` 汇总已确认的同一人物，不能按昵称合并。

上下文消息顺序为：固定系统/阶段规则与工具定义 → 最近成功的会话压缩摘要 → 检查点后逐条追加的完整消息流 → AI/人物画像、群规则、相关Topic等动态资料 → 本轮时间、身份与问题 → 本轮工具往返（如有） → 应用本轮控制块。摘要和历史作为独立pa_conversation_context消息置于pa_memory之前，避免动态画像或时间打断历史前缀。相同执行阶段切换表达模式时，system和旧历史前缀保持稳定；准备/回答阶段的协议与工具可用性仍不同，供应商是否命中缓存以实际usage为准。

2026-10-26人物展示统一使用`context-people.ts`：稳定`U_`标签仅由实际person_id确定，不按本轮出场顺序或昵称编号，不作为工具参数或授权键。消息/引用/历史工具的`speakerLabel`指真实发言者，`BOT`指本Bot，`UNKNOWN`表示缺少可靠人物绑定；历史AI消息的`replyToLabel`指其原提问者。画像和明确共享事实的人物附`personLabel`，本轮`replyTarget`放在动态输入末尾。没有每轮变化的全员索引插在摘要和历史前面，旧消息的显示名沿用原记录；首次切换投影会改变缓存前缀，之后仍按原顺序追加。标签不推断描述对象、不增加跨房间读取或模型调用。平台引用仅在本房间已确认来源及单条正文匹配时继承可靠Bot身份，显式真人作者冲突时不继承；内嵌未知作者不按昵称绑定。压缩/Topic提示保留人物标签及可用称呼，输出仍用现有摘要字符串，预算/触发时间不变；旧原文、画像修订和冻结输入不重写。确定性测试验证绑定和投影，人物理解质量保留为真实模型评测样例，不要求程序对任意模型错答提供语义证明。

只在完整请求含输出预留达到实际上下文窗口85%时触发后台整理，不再按50条或50轮触发，也不硬编码1M。Topic继续用于房间内FTS5/BM25检索，continuationSummary承接旧摘要和完整增量，二者在现有整理事务中一并提交。

窗口估算复用同接口、模型和房间的成功SDK实际输入（含缓存），按请求分块指纹匹配稳定历史，对新增/变化内容继续保守计量。无可靠样本或上下文大幅换代时回到字节备用估算；样本随已有诊断记录保存，不进入模型提示词。准备阶段的usage可立即用于本轮下一次请求，85%判断及最终请求的硬上限均使用校准估算，仍保留输出/工具和安全余量。

## 循环、专业模式与存储

- 默认 `PA_LOOP_MAX_MODEL_CALLS=6`、`PA_LOOP_MAX_TOOL_CALLS=8`，不设整次总时限。`PA_TIMEOUT_MS`限制单个模型请求；网络工具和后台调用各有独立请求超时，主动取消仍可中止准备和工具等待。QQ的被动回复有效期属于平台投递约束，不是Agent循环计时。
- 最后一次模型调用去除工具，预留收尾；执行层再次检查，模型违规输出工具调用也不能突破上限。Schema 无效调用不产生业务写入。
- 准备阶段选择回答模式，同一Pi会话继承身份、证据和剩余预算；专业答案直接保存发送，不再调用日常模型重写。
- `web_search` 的摘要与来源留在工具结果中，来源可继续用于 `web_fetch` 核验；搜索回答不展示来源网址或自动追加参考链接。只读取网页且没有搜索的回答仍可附原网页URL。
- 所有渠道提问进入持久任务队列，`PA_MAX_CONCURRENT_TASKS` 默认2（范围1–16）；每问使用独立 Pi 转录和锁，SQL、人物画像和后台整理仍按真实房间与人物关联。计算完成就释放计算槽，等待发送不会占着它。每房间的发送队列一次发送整条回答，进度也经过这条队列；不同房间可以同时发送。
- 等待提示已接入prepare_turn后的专业/资料查找流程，也可由progressText指定；普通短答不默认发送，准备回执有错误时不自动发。真正调用web_search/web_fetch时也可提示，每轮统一最多尝试一次，不依赖旧answer_in_depth工具；群聊与私聊共用此机制。research只代表意图，默认短句不假称已经搜索或取得结果。
- 等待提示只在房间输出空闲、harness未关闭且被动窗口仍有效时准入；检查到队列占位之间不异步让出。忙或过期直接跳过，不创建进度记录、不占回复槽，后续工具也不补发迟到提示，保持同群正文段不穿插。已准入的短提示仍等待其发送回执；若这次transport慢，会占当前计算槽，但不会在旧正文队列后等待。进度create/start/ack持久化失败停止会话，不能降为普通网络失败。
- QQ 的进度提示独立保存在 `run_progress`，不是聊天原文或人物证据，也不计入整理条数/轮数。窗口内使用原消息ID和下一个回复序号，进度与正文合计最多5个槽位。QQ回答使用原生Markdown，长回答按不超过1500 UTF-8字节自动分段；代码围栏跨段闭合并重开。同房间按批次串行，整批超出剩余被动槽位或窗口过期时转主动发送。逐段确认并记录引用索引；拒绝或未知投递立即停止，重启不自动重发。完整回答作为一次AI消息进入上下文，`/result` 可重新领取完整正文。旧分页数据只为历史读取和引用解析保留。见[Markdown 长回答](../qq-long-replies.md)。
- `/result` 或 `/result 任务编号` 可领取当前房间中本人已完成的结果，不调用模型。主动答案附昵称、问题摘要和任务短编号。重启继续尚未开始模型处理的 queued；已有运行的失败、中断和未知投递不自动重跑，完成答案仍可领取。主动发送可能受QQ权限或平台额度限制，代码不绕过这些限制。
- 当前使用腾讯官方群/私聊消息接口，公开契约没有截图中的“合并转发聊天记录”消息结构。[官方发送文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)与[NapCat合并转发接口](https://napneko.github.io/onebot/api)属于不同接入方式；本次没有切换QQ客户端协议。

## 工具错误恢复

准备参数校验（包括Pi执行前的schema校验）和业务拒绝以错误工具结果交回同一循环，仍消耗原有次数预算；未成功准备前仅允许prepare_turn，成功后禁止重复保存。MemoryError返回tool_request_rejected，不把拒绝冒充保存成功；真正持久化错误、取消和未知模型请求失败继续硬停止。

回复含无回执保存承诺时，最多用剩余预算中的一次模型请求改写，关闭全部工具；没有剩余额度或改写仍不合规时，以明确未保存的短回执替代。短回执和正常回答一样写入Pi记录，保证投递恢复读取相同内容。同批研究操作部分成功、部分参数错误时保留成功回执，并允许失败项在预算内修正；未修正的失败在最终确认中明示。
