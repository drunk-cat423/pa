# 整理协议 v2：按处理范围记账，按用途保留证据

## 问题与取舍

原协议要求每条真人消息进入Topic、人物片段或ignoredMessageIds。该清单只能证明ID被列入结果，不能证明模型完整理解消息；它却让输出长度随聊天条数线性增加。把每个Topic连到大量消息还混淆了生成背景与事实证据。

保留SQLite原始消息的稳定ID。ID对幂等、回复引用、身份和审计有价值，数据库保存一次的成本很低；取消的是让模型重新抄写全部ID及逐条分类，不删除消息ID或原文。

对话压缩与资料整理分为两条流水线，共享任务外壳、日志和费用预算，分别记录顺序、固定输入、成功进度与错误。每个任务可以包含多个可恢复步骤，最终只原子提交自己负责的产物。

对话压缩按85%容量条件创建任务，只更新续聊摘要与对话压缩水位。资料整理独立从数据库原文提取Topic并合并人物/AI画像，不生成续聊摘要，不推进压缩水位。资料任务运行或失败不会阻挡压缩；前台硬上限等待只观察压缩流水线。

## 资料整理的10/30分钟计时

检测到尚未预约的新真人聊天或新画像pending时才开启一轮，持久保存首条和最后一条新增的检测时间。空闲10分钟或从首条新增起30分钟，先到的条件预约一次任务；同一事务捕获本批原文及pending，并同时清空两个时钟。没有新增内容时不会自行开启下一轮，重复轮询、重复渠道事件、控制消息与AI回复本身不刷新计时。

模型运行期间的新内容开始下一轮；上一任务提交只保存自己的结果，不清理新一轮计时。重启恢复已保存时间，已到期且尚未预约的轮次只预约一次。pending可能晚于原消息入库，单独观测新增ID；本批只处理预约时固定的pending，之后新增的建议留给下一批。已处理或deferred条目本身不反复启动计时。明确的画像更新仍当轮保存、下一轮可参考，无需等定时整理。

## 三种来源粒度

| 数据 | 模型返回 | 程序保存的来源 |
| --- | --- | --- |
| 续聊摘要（压缩流水线） | 完整滚动摘要 | 压缩任务固定成员、前一摘要版本、已完成步骤区间 |
| Topic | 少量有用的摘要 | 父任务ID及生成步骤的起止ordinal |
| 人物画像、AI画像 | 必要更新及少量关键证据 | 精确原始消息ID、人物身份、版本、pending处理回执 |

Topic区间不意味着每条消息都支持该Topic。查原文时使用父任务的固定有序成员，不用最小/最大ingestSeq推断成员，避免晚送达、其他房间消息和deferred缺口混入。新Topic不再通过来源交集附加历史人物片段；旧精确Topic关联保持可读。

明确纠正仍有优先权。若新Topic的来源区间包含已失效旧说法，前台保守跳过该Topic；不能因为精确ID列表为空绕过纠正过滤。画像事实继续逐条校验证据归属，不能将他人陈述当成本人自述，也不把AI回复当真人证据。

## 模型协议与执行范围

新滚动输入使用extractionProtocol=2，contextProtocol=1与profileProtocol=2的含义不变。压缩只输出continuationSummary，资料整理只输出topics、profiles及本步骤捕获的selfProfile结果。不输出逐条忽略清单、人物事件片段或程序处理回执。

消息、人物和两类pending使用本请求内的m/p/q/s短引用。映射由冻结输入确定，响应只在结构字段中解码；正文中的相同字符串不替换。未知引用、跨人物pending、额外字段及模型伪造的来源范围立即拒绝，再执行原有证据和权限检查。日志保留原始模型响应以及哈希校验的规范化输入，足够离线重建映射。

步骤完成后程序追加processedRanges；提交前检查区间无洞、无重叠、完整覆盖父任务成员，每个Topic对应一个已完成区间。这证明执行步骤完成，不宣称逐条语义均被验证。没形成持久资料的闲聊可以自然略过；仍可从原始历史独立查回。

## 预算和失败行为

对话压缩保留自动85%窗口触发；资料整理使用独立10/30分钟计时。输入预检继续使用实际模型窗口和图片限制；输出只为本流水线允许的产物预留空间。Topic最多8条、每条400个Unicode字符、单步正文合计最多2000字符；实际小输出预算会进一步降低上限。画像维持既有硬限制和较小的收敛目标，完整旧事实仍进入整理输入。

能容纳时保持一次模型请求。需要拆分时，消息按序滚动摘要，人物步骤保留该人的完整画像，AI pending可分步处理；跨人物第三方陈述仍保留在同房间上下文，不能仅按发言者裁剪。没有AI pending时不要求重复输出AI画像；消息步骤不反复处理AI pending。输出估算不是分词器实测，不能保证模型一定遵守篇幅，真实截断仍明确失败且不自动付费重试。

进度v3保存已完成步骤、归纳结果和少量范围回执。资料成功后同一事务提交Topic、人物画像、AI画像、pending审计及清理和资料处理进度；压缩只提交滚动摘要与压缩水位。提交失败全部回滚，原始聊天不动。重启和显式重试只接续尚未成功的步骤。新协议版本冲突保留原冻结输入与进度，不允许普通retry变换其证据或重新收费；操作者须显式搁置后建立新快照，旧任务不标成功。

## 旧数据与验收

schema20新增Topic范围旁表。schema21保留任务rowid顺序及原有全部字段，新增流水线标识、独立资料状态/固定成员/待办捕获表，并用隔离旁表保留旧未完成混合任务的输入和进度哈希；原状态、租约、错误和JSON原样保留，拒绝自动领取、普通重试和迟到提交。旧成功资料覆盖根据实际任务成员恢复，不复制摘要游标猜测；旧未完成范围不视为已整理，也不自动收费重提炼。没有extractionProtocol的旧冻结数据与进度v2继续可离线解析，旧purpose=memory协议仍明确失败。原文、旧关联、画像版本与向量历史均保留。

schema22新增显式人工回填审计。操作者冻结当前可见截止，按条数/字节拆新materials任务并定向捕获有效pending；旧隔离/退役任务原行与证据不动。已完成旧成员和已被材料任务拥有的成员不重复预约。回填worker只执行指定run，不启动计时、不跳过前序任务或自动重试收费调用；成功不推进压缩水位，原始记录及旧版本保留。

离线验证覆盖2000消息的有界输出、严格短引用解码、精确范围成员和跨房间隔离、纠正过滤、缺口/重叠回执拒绝、原子回滚、预算拆分中的第三方资料、AI pending失败后的重启续接、19到20及20到21的保留式迁移，以及双计时和两条流水线隔离。模型提炼质量和真实费用仍需单独授权联调。
