# 已确认效率问题的修复与检查

2026-10-30 审查基线为 `3270f41`。本轮保留两阶段、完整增量历史、85%容量压缩、身份权限、失败恢复和未知投递不重发；不新增产品功能、不改变模型或思考强度。

## 调用与投递

- 搜索额度只在预约和终态记录时持有跨进程文件锁，网络请求在锁外；进程内最多4个搜索，等候可取消。预约仍先持久化，失败/未知调用不退回次数，不重新发送；旧JSONL计数兼容。遗留锁不自动删除，短锁等待5秒仍未获得则报占用。跨进程共享预算不超额，4个网络槽只约束当前进程。
- 研究保留单计算worker，通知有独立单投递worker。完成状态仍是持久通知队列，慢通知不阻塞下一项研究；wait/关闭会等待两者。真正发送前再次检查归档、续作和关闭状态，沿用房间完整输出队列及未知不重发规则。
- 领取研究任务/通知使用SQL路由过滤及LIMIT，读取任务元信息；checkpoint不解析历史材料。实际研究阶段才按业务需要读取当前任务材料，单条补读直接查询对应编号。旧维护接口保留完整读取语义。

## 本地热路径

- 上下文查询在SQL里从摘要cursor读增量，再按消息主键合入旧缺口；旧时间边界需要完整历史时仍正确回退。资料完成水位从已确认位置推进，迭代遇到第一个未覆盖原文即停止。
- 记忆worker自己排空可领取任务，空轮询结束后不再汇总全部历史状态；非done任务使用局部索引。Trending的待发送、过期查询也使用局部索引，无待过期项时不预约写事务。
- 图片一次构建读取并校验原图一次，元信息和模型内容复用该次结果；不把原图永久缓存到内存。每轮和read_image仍复核访问权和文件完整性。
- 容量估算保留准备/全部回答模式的最大值，仅在同一次估算中复用精确字符串分片哈希；分区、上界、校准样本及实际模型payload不变。调用结束释放缓存。
- 诊断校准增加兼容v1的局部表达式索引。旧库首次由runtime显式写入口补建，可能扫描旧索引数据一次；诊断读取和服务器只读巡检不建索引，不改历史正文。
- 同一harness的房间连接共享初始化核验scope，文件身份或schema变化时重新检查；新harness及独立维护工具仍做完整检查。每个连接独立启用外键与FULL/WAL持久化设置。只增加索引，没有提高业务schema版本。
