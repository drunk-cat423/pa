# 当前运行机制与存储边界

这份清单说明已经存在的行为及触发条件，不代表新增功能。具体是否启用仍取决于实际配置。

## 一轮聊天

QQ 入站先保存原文、真实发送者、@ 和附件关联，再按房间排队。SQLite 保存 PA 聊天及记忆的业务状态；Pi 每轮使用内存会话，不写新的 JSONL，也不读取旧 Pi 文件来决定是否允许聊天。

模型默认经过准备和回答两个阶段。准备阶段通过 prepare_turn 判断模式、提交当前明确提出的画像等更新；研究、提醒及历史查询使用工具循环，最终按真实回执回应。群聊跨人物经历引用可能额外进行一次有界归属核验，现况问题可能要求先搜索；这些请求计入原有调用预算，不是无限自动循环。

输入按固定提示、最近压缩摘要、检查点后的完整文字消息、动态身份/画像/本轮信息组织。图片原图默认只随本轮当前消息或当前引用附件发送，先做元数据容量预检；后续可通过 `read_image` 在原房间按权限复看。历史保留图片标识、归属、引用关系及已经发送的识图回答，不额外逐图调用模型生成描述。

## 除原始聊天外，还保存什么

- **人物画像及 AI 自身画像**：已归档与未归档。当前明确更新先保存 pending；新增资料空闲10分钟或累计30分钟先到时触发后台归纳。身份权限由真实来源决定，不由画像或文字中的名字决定。
- **群规则、术语与普通群共享事实**：已有管理者工具维护，仅在本群使用。它们仍与个人/AI画像分开。普通纠正保留在聊天，涉及画像就更新画像，不再建立独立归属纠正区或强制注入纠正链。
- **continuationSummary**：容量达到实际模型窗口的85%时生成，之后从新检查点继续积累完整历史。没有50条/50轮阈值，原文不被摘要覆盖。
- **Topic**：后台资料整理生成的历史讨论资料，按来源房间通过 FTS5/BM25 检索，只作当前问题的辅助背景。它不是另一份必须信任的聊天记录，也没有人物向量检索。
- **研究任务与报告**：本人统一清单、独立后台执行，结果正文单独存文件；普通聊天不注入整份报告。单项失败/未知不会自动反复开启收费研究。
- **一次性提醒**：持久保存时间、事项、身份和发送状态，到期发送不调用模型。提醒不是自动执行研究或编码的入口。
- **Trending 日报**：配置群按 `trending-schedule.ts` 定时发送（当前北京时间08:50），独立日期账本防重；任务生成与投递分开，正文不进入个人画像。
- **Codex 及发布任务**：仅配置的本人QQ私聊可派单；独立执行器的 tasks.json 是执行器任务账本，独立发布器还保存其发布记录。这些记录不与 Pi 争夺聊天真相；发布必须由本人原始消息确认。
- **诊断**：模型请求、响应、工具过程、用量和最终答复证据独立保留。完整且绑定输入的最终证据可恢复未落库答复；超长答复不内联到受限大小的诊断事件，仍正常提交SQLite，若恰在提交前崩溃则保守视为未完成；证据不足的旧运行标 interrupted，未知模型/工具执行不自动重放，未确认的QQ投递不自动重发。普通聊天诊断目前没有自动过期清理，会保存多轮请求/响应；研究正文另有30天保留规则。这是独立执行证据，不是另一份聊天状态。

## 已退出运行路径的设计

旧 Pi JSONL、schema31核对账本、旧归属纠正表及修订不物理删除，只留作历史审计。新聊天和新压缩不依赖这些记录，不会因旧 JSONL 缺失或损坏隔离房间，也不再替换旧原文为 correctedBy 占位。SQLite 的事务、外键、身份授权和真正持久化错误检查仍保留。

## 修改如何验收

`node scripts/repo-check.mjs --changed src/文件.ts test/新增.test.mjs --list` 可查看相关回归和本次新增/修改测试的合并选择。未知源码模块回退全部现有回归。

发布器以受限构建账号执行候选代码的编译和相关测试，将 commit、补丁哈希、验收命令及退出码保存在独立 validation.json。测试通过才继续发布；模型的“已测试”自述不替代实际验收。
