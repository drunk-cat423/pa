# 画像归属与交流表达

用户画像记录这个人希望如何被称呼、如何被回应等本人偏好；AI画像记录当前本Bot的名称、定位、全局表达风格与长期关注。判断看被描述对象和适用范围，不看是谁说的、句中是否出现“我”。其他Bot的名称不归到本Bot，个人的短答偏好不自动推广给所有用户。

前台`prepare_turn`和后台归纳共用`profile-policy.ts`。例如用户明确纠正“X指的是你”且对象为本Bot时，应提交`ai_self`；“以后叫我X”提交`sender`。这属于模型语义判断，不增加正则分类、自动重路由或更严格的程序校验；真实来源、身份权限、版本、预算和保存回执保持原行为。问候和情绪分享本身不触发画像更新，也不借当前消息补写旧历史要求。

AI画像的名称、定位和表达习惯是持续交流设定；人物背景、Topic按当前问题相关性使用。通用提示描述伙伴定位，模式规则只调整当前回答方式，画像描述个性，避免三处重复堆叠风格禁令。闲聊像朋友一样顺着具体的人和事接话，分享本身不需要评价感受或给出建议；认真提问时按需分析。提示中不嵌入某次真实对话的理想台词，事实准确性和身份权限边界仍沿用现有规则。

称呼纠正后只确认本次实际变更，不自行规定主称/别名场景或为其他设备补名称。人物画像中的旧说法不能覆盖当前对本Bot的明确纠正。历史消息继续完整保留，AI设定仍在原动态背景位置，不因风格改动重排历史或改变两阶段。

后台self组件仍只处理AI待归档区；已错放到人物画像的旧内容不会自动迁移。历史归位需审阅具体条目和来源，保留旧版本；正式操作遵循现有备份与版本核对。本次仅在私有隔离预览中准备已确认别名的候选归位，不改生产画像。

验证分两层：现有`person-profile-policy`增加一项本机HTTP/临时库链路回归，证明给定正确计划时AI pending、下一轮实际payload、归档来源与个人偏好隔离；这不能证明模型分类准确。真实模型对比使用获授权的私有历史快照，在独立数据目录运行，不发送QQ或修改生产。历史答复与候选回放不是随机A/B，不能据此承诺总体质量或性能改善。真实语料、画像草案和结果只留忽略的`.local`，不进入Git。

工具准备失败要追到具体`toolResult`，不能仅根据最终“未完整返回prepare_turn”定因。同一真人消息允许多段连续原文引用；每段仍分别验证消息可见、有效真人、原文和真实人物绑定，数量与长度上限不变。该故障用现有`answer-grounding`中的一项真实Pi/本地HTTP回归覆盖，不增加模型重试次数。

修改表达时，默认沿用完整历史和现有归属修正，先冻结基线，再用少量原失败对话和不同内容的留出问题回放，失败和不佳结果也保留。用户允许开发中裁剪时，可另做精简历史的对照，保留理解当前问题必需的原始消息，并记录哈希、长度和剔除范围；再单独比较不相关画像或检索资料的影响。原始证据不删除，这不等于已实现线上历史裁剪策略；短上下文仍有坏回复时，不能宣称长历史就是根因。

单独核对最终payload的同阶段固定system、工具及完整历史前缀，运行`cache`专项；记录提示长度、模型调用次数、实际用量和耗时。固定提示改版后的首次冷缓存不等于每轮前缀破坏，小样本耗时也不能证明线上加速。可复用流程保存在仓库的[companion-prompt-eval Skill](../.agents/skills/companion-prompt-eval/SKILL.md)，本机已安装副本；本页保留项目契约，Skill不注入PA产品提示词，也不授权自动部署。
