# 记忆系统 v1

当前实现为 TypeScript / Pi SDK / Node 内置 SQLite。规则来源是 [逐项确认方案](design/companion_memory_v1.md)。代码已完成离线集成验证；后台默认关闭，真实整理模型质量、QQ @ 对象的真实事件仍需联调。

## 人物、话题与原文

actor_id 保存某个人在某个房间的发言身份，person_id 汇总经过确认的同一人物。未绑定成员先使用独立人物记录，不按昵称合并。人物画像在绑定的群聊与私聊中共同使用，管理权限继续独立由 ownerBindings 决定。

`PA_DATA_DIR/policy.json` 保留原来的 primaryPerson，并允许多个 persons：

```json
{
  "version": 1,
  "ownerBindings": [],
  "persons": [
    {
      "id": "person_alice",
      "bindings": [
        {"route": {"channel": "qq", "accountId": "APP_ID", "roomType": "group", "roomId": "GROUP_OPENID"}, "senderId": "MEMBER_OPENID"},
        {"route": {"channel": "qq", "accountId": "APP_ID", "roomType": "private", "roomId": "USER_OPENID"}, "senderId": "USER_OPENID"}
      ]
    }
  ]
}
```

填写实际平台 ID；群成员 OpenID 和私聊 user_openid 不靠字符串相似度对应。绑定变更保留历史版本，已有独立人物归纳的事实及人物片段会随首次明确绑定合入目标人物，保留片段ID、正文、来源关联和旧画像修订，较新明确事实优先。

每次回答只直接读取当前发送者和本条问题真实 @ 对象的画像，重复对象去重。普通文本人名、历史 @、@全体和 @Bot 不增加人物候选。画像按上下文预算取用完整事实，不做人物向量或 FTS 检索。

群聊自动提供当前问题之前、本群最近10条真人聊天作为候选背景，按入库顺序排列，不限定发言者或10分钟；不含Bot回复、控制消息、本轮及之后消息。原文已整理、相关问答失败或未回复都不影响这10条的选取。背景明确标注可能无关，不自动认作当前提问者的发言，不顺带回答或触发历史中的保存要求，也不因为背景出现某人而额外加载其画像。私聊历史与摘要、已保存记忆和检索Topic同样只是候选背景；是否相关由当前任务决定，不能将检索命中等同于相关或真实。显式引用是用户本条选定的材料，内容也要按问题筛选。身份、时间与保存回执的权威范围分别限定于身份/权限、时钟和操作状态。

Topic 保存有原始消息 ID 的具体讨论；人物片段标记自述、第三方陈述或推断；画像是当前已归纳状态。Topic仅按来源房间使用中文FTS5/BM25检索，不做向量匹配。原文按房间保存，人物画像共享不复制其他房间全部历史。

## 后台整理与并发

- 群聊每 50 条去重真人聊天消息；私聊每 50 个成功且已确认发送的完整问答触发。失败或未发送回复不凑轮数。
- 最终请求占用含输出预留达到窗口 85% 时也触发，可以不足 50。当前使用 UTF-8 字节量加协议/安全余量的保守估算，不把字符数当精确 Token 数。
- 固定消息 ID、起止序号和任务状态后再请求模型。新消息立即入库；后台与聊天独立，同房间整理按序，不同房间可并发。
- 成功时同一事务保存 Topic、片段、画像修订和检查点。失败保留固定批次和诊断，仅显式重试重新排队，旧租约不能提交。普通失败保留成功子批；版本冲突清除失效派生输入/进度以便显式重读，固定消息成员和原文不变。过长批次拆分后持久保存子批次进度。
- 请求超过硬上限时，等待相关批次完成后重新构造请求；等待有截止时间。无可压缩历史或当前输入仍过长时返回失败，不发送超限请求。
- 私聊前 50 轮完整历史仍受容量线约束；之后用续聊摘要、画像、相关 Topic 和未归纳对话继续，原文保留。群聊没有独立群摘要。
- 每秒巡检只检查是否达到批次条件、是否有可执行队列，不是每秒调用模型。未开始的排队任务可在启动和巡检时继续，不要求先收到新消息。关闭取消在途调用；失败、过期租约或结果未知的调用不自动重调，等待显式重试。
- 本地操作者可显式搁置失败批次，保持原 `failed` 行、冻结输入、进度、错误和固定成员不变；旁表记录原因、时间及输入/进度哈希。普通失败仍阻塞，已搁置批次从执行队列排除，后续继续按序领取/提交。状态分别显示 `failed`（仍阻塞）和 `deferred`（已搁置）。搁置不是完成：连续水位不跨缺口，缺口原文仍保留，私聊摘要与后台输入用 `deferredRanges` 明示未覆盖区间。搁置批次禁止普通 retry 和迟到提交，避免旧画像或摘要覆盖新状态；补录需另行设计，不能直接改版本重放旧结果。

模型提案经过结构和来源检查；画像更新使用版本 CAS，旧批次不能覆盖较新自述。人物画像协议 v2 提供完整人物画像并返回完整替换结果，不再裁掉旧事实后自动补回；必要时在同一固定批次内按消息、人物或 pending 分块，进度持久保存。完整人物画像及必要来源本身放不下时明确失败，不把局部视图冒充完整画像，不自动调用模型修复。

### 人物画像容量与 pending 生命周期

当前生效画像同时限制为40条事实、每条200个Unicode码点、正文合计6000个UTF-8字节，以及 `{personId,baseVersion,facts}` 完整结构16000字节；每条只携带最多5个代表来源。正文及结构是字节上限，不是token预算，也不包括独立限量的active pending。达到30条、4500字节正文或12000字节结构时，下一次既有后台批次必须给出完整收敛结果；不单独因75%阈值发起模型调用。新版本在去重合并后和事务写入时均校验硬上限，不静默截断，不无限并回未展示旧条目。历史已超限的旧版本不在迁移中裁剪，后续完整整理成功后才切换当前版本。

模型依据真人来源合并同义事实、处理较新明确纠正、精简表达，避免把临时事件或一次评价固定为人格。达到软线时尽量收敛到软线以下；程序不能判定语义等价或保证模型提炼质量。安全校验不通过时保留原画像及原文。完整历史仍保留，不新增人物历史检索或个人长期事件模块。当前每轮载入预算继续独立生效，并非每轮必须载入全部40条。

每条已捕获的待整理资料必须有明确处理结果：`merged` 指向新画像中的事实，`superseded` 指向更新且属于本人的保留依据，`not_profile` 标明临时信息/非个人资料/证据不足，`deferred` 继续等待。新增、跨人物、已被处理或内容变化的pending不得借旧快照处理；本人自述不能被更晚的第三方说法直接覆盖。

成功事务同时写入新画像版本、`person_profile_pending_results`无正文回执和`person_profile_revision_sources`来源关联，然后物理移除非deferred的active pending。这样释放待整理名额和正文额度；deferred继续保留正文，旧已归档pending不批量清理。原始聊天、旧画像版本、冻结输入和诊断证据仍保留，因此不承诺SQLite文件会立即缩小；这只是内部成功队列的清理，不开放用户删除画像/原文的命令。

新固定输入标记 `profileProtocol=2`，分块检查点使用独立版本。旧冻结输入或旧检查点不会被静默改写成完整替换协议；真实工作器明确失败并保留原快照/进度，交由本地操作者处理，纯离线诊断仍可解析旧格式。尚未捕获输入的排队批次在首次执行时使用新协议。

## 启用及预算

在已有 `.env` 中按 `.env.example` 补充：

```dotenv
PA_MEMORY_ENABLED=true
PA_MEMORY_MAX_CALLS=20
PA_MEMORY_TIMEOUT_MS=120000
PA_MEMORY_MAX_OUTPUT_TOKENS=8192
```

启用会增加调用费用。后台复用聊天provider/model，独立会话、输出预算和超时；所有房间共用PA_MEMORY_MAX_CALLS，0表示不限次数。失败请求计数，超限拆分的本地预检不计实际请求。SDK重试关闭，失败/未知调用仅人工明确重排；已取消未生效的PA_MEMORY_MAX_RETRIES。

Topic仅按当前房间用中文分词FTS5/BM25读取，状态为lexical，每个Topic最多携带5条与其自身来源相连的事实，不读取其他房间证据。向量配置、Embedding接口、预算、派发与相似度/RRF运行逻辑已移除；旧向量表与attempt原样保留，不读取、不重新派发。

## 显式更新与管理

### AI 自身画像

AI 自身使用一份跨场景的全局画像，和用户画像分开。SQLite 保存“已整理画像”和“待整理补充”，不维护第二份可写的画像文件，也不增加针对某个人的相处模式。

允许接入场景中的任何成员都可以提出明确补充，无需管理者身份。群聊仍须真实 @ 机器人，私聊遵守已有白名单。例如：

```text
请记住你的名字叫初号机
你记住一下，你以后回复不要太正式
你记一下以后回复简洁一点
以后你的回答简洁一些
/self 解释复杂问题时先给一个直观例子
```

渠道自然语言统一进入同一 Pi Agent Loop 的强制准备阶段：第一请求只开放 prepare_turn，返回 intent、mode、updates。没有持续保存意图时 updates=[]；不以程序匹配“记住”前缀代替模型理解。每轮最多8项、总共20000字节，content必须连续摘录当前消息；个人每条最多4000字符，AI每条最多500字符。harness逐项验证身份、范围和容量，在同一SQLite事务提交全部更新与来源消息级幂等回执，再请求正式回答。任何一项越权则全部回滚，不能部分确认。保存成功与回答/投递成功分别记录，回答失败不会擦除已经提交的资料。

prepare_turn 的 target 可为 sender、mentioned_person、ai_self、room_rule、room_memory。普通成员仍只能保存本人资料和建议AI全局画像；mentioned_person仅管理者可用于当前消息明确指向的已知成员，并固定为third_party证据。群规则和群共享事实仅管理者可写，且仅当前群有效。sender/mentioned_person仅用于稳定画像；不再提供purpose字段或个人事件保存。个人经历、一次性计划不因取消模块而改存为画像或群记忆。

准备后回答阶段关闭画像写入和旧的深度切换工具，mode=casual/standard/professional只选择表达提示，不改变权限。普通请求至少2次模型调用（准备、回答），均计入原有每轮6次预算；历史与网络工具续轮额外占用同一预算。准备阶段目前验证了OpenAI兼容协议，其它供应商协议未接通时请求前明确拒绝，不退回不受约束的保存。模型忽略强制准备、并列其它工具、无保存回执却作出明确保存宣称时阻止发送；这不等于已验证模型对所有自然语言意图都能正确分类。

个人与AI画像均只分已归档和未归档。新画像建议先保存在pending，下一轮连同归档画像注入；个人事件模块已停用。旧purpose=memory pending及个人memories保留，不注入、不查询、不纠正、不转成画像。已冻结输入或进度若包含旧个人事件协议，会明确失败并保留原JSON，等待操作者处理；普通重排不会暗中改写旧协议。画像只用于措辞、例子、偏好与风格的软参考，不作为回复提纲反复复述，不暴露内部标签或提供普通成员的画像导出。旧审计分类元数据保留，但不会要求模型继续输出。

每轮提供当前发送者与真实@对象的身份卡，即使暂无画像也保留身份；显示名与稳定person_id分开，维护者身份按当前平台账号及房间的ownerBindings验证，人物合并不授予权限。

### 群规则与术语

“本群pa代表personal agent”保存为本群规则，而不是人物或AI画像。room_rule_revisions按群、规范化key、revision保留原文和来源，纠正生成新版本；仅当前群注入，不能改变身份绑定、权限、工具白名单或预算。规则最多50项、当前版本总计12000字节。不同群独立；私聊不创建群规则或个人事件记忆。

历史误分类通过明确的本地维护计划迁移，不用模型批量猜测：reclassifySelfProfileTerms核对pending ID、预期原文、原群及ownerBindings，追加群规则和画像投影修订，并在self_profile_reclassifications关联前后版本。旧原文、pending和修订不删除，活跃画像及其容量计算排除已迁移条目。已有归档、目标规则冲突或来源无群管理权限时拒绝，不能借迁移把普通成员或私聊建议提升为群规则。该操作不是聊天/模型工具，也不改变任何权限配置。已有后台输入快照保留，旧提取结果不能将已迁移来源重新写回AI画像。

历史由read_history工具按当前房间和发言者过滤，使用中文分词后的SQLite FTS5/BM25检索；没有关键词时可按时间读取最近记录。默认当前发送者，群内可查询本群其他成员；每次最多10条，包括对应问答补充。已整理原文仍可查询，不扩展人物FTS或向量检索。完整流程、提示词结构与循环限制见[工具循环流程图](design/companion-tool-loop.md)。

下一次50条/50轮或85%容量整理使用同一次模型请求，额外输出自我画像合并结果。不强制每批形成新性格；无新依据时保留旧内容。已处理条目标记归档，保留原文、来源和修订；仅归档任务快照中明确处理的ID，在途新增继续待整理。跨房间同时更新使用全局版本检查，旧结果不得覆盖新版本。AI自己生成的发言不能单独作为自身事实证据。

每条建议最多500字符，待整理正文最多12000字节、100条，并与正式画像、来源ID等一起受实际上下文窗口15%（最多20000字节）的预算限制。超过容量会明确拒绝本次保存，不回执“已记住”；可等待整理或缩短建议后重试。固定系统规则、权限、工具与预算仍由程序和本地配置决定，不能由画像修改。

普通成员可提出本人画像补充或AI全局画像建议，由模型调用工具保存，不获得管理其他人物、导出全部档案或改变身份绑定的权限。保存不要求用户选择分类。

管理者保留 `/memory remember room 内容`、`/memory query`、`/memory correct ID 内容`。这些显式管理指令由程序鉴权并执行，成功短确认；查询结果、权限拒绝、澄清、报错和命令帮助直接返回。离线 CLI 保留 remember/query/correct，仍不调用模型。管理查询仅覆盖当前会话群共享记录；me/user个人目标和旧个人记录ID均拒绝，人物画像通过自然语言更新，不导出普通成员画像。QQ私聊不创建、查询或纠正房间记忆；CLI离线房间管理保留用于验证。需要群记忆ID时通过管理查询获取。

```powershell
npm start -- memory remember --conversation owner --content '本群pa代表personal agent'
npm start -- memory query --conversation owner --query 'pa'
npm start -- memory correct --conversation owner --id ID --content '本群pa统一指personal agent'
```

不提供 delete、/forget 或自然语言删除；旧命令本地拒绝，不擦除记录。平台撤回也不删除已保存原文。纠正保存修订并更新当前值；数据库记录“某人曾说过什么”，不把所有陈述自动视为已证实事实。

后台诊断与重试无需模型密钥：

```powershell
node --env-file-if-exists=.env dist/memory-jobs-cli.js status
node --env-file-if-exists=.env dist/memory-jobs-cli.js retry JOB_ID
# 先暂停后台并确认运行进程已加载PA_MEMORY_ENABLED=false，再搁置：
node --env-file-if-exists=.env dist/memory-jobs-cli.js defer JOB_ID "保留失败批次，等待单独补录"
```

retry 只重新排队，启用后台记忆的服务在巡检或下次启动时执行，因此人工重试会再次调用模型。失败、进程中断或租约过期不自动重试未知结果的收费请求；原文、固定批次、已成功子批进度保留，后续同房间批次保持顺序。状态输出含任务ID、状态、阶段和经过白名单筛选的错误类别，不包含供应商原始错误、原文、画像或密钥。QQ服务状态显示任务数量与共享调用次数。

`defer` 本身不调用模型，但在运行中的服务启用后台时，会使后续批次恢复收费调用资格。禁止收费联调时，先停止服务、备份数据及配置，将 `PA_MEMORY_ENABLED=false` 并重启确认生效，再执行搁置。保持后台暂停可验证领取资格与数据保留；后续批次尚未实际整理，不能称为已清空积压。恢复后台需明确允许费用。

提取先读固定原文批次与已有事实，产出有证据的原子片段、Topic和必要的稳定画像修订。同人同内容、同来源类型的重复片段合并证据，不跨人物去重；画像同义归并由提取模型提出，程序校验来源和版本，不能把相似度当作事实相同。事件与讨论不自动转为人格。ignoredMessageIds只列未用于Topic/片段的真人消息，机器人回复只供理解上下文，不参加真人覆盖计数。
