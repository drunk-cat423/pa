# 对话提示词实测

交付实际回复和可核验的结构、开销变化。把“听起来像朋友”转成少量行为目标，例如围绕正在分享的事接话，认真求助时仍能给出有用意见。无需把每种坏回复都写成一条禁令。

## 保留基线与权限

- 先定位真正发出的 system、模式规则、画像与历史，不只看某个提示词常量。保留任务开始时的 diff 和基线，避免覆盖已有修复。
- 回放沿用同一历史、当前消息、模型、工具、来源身份和输出预算；更换画像时单独记录。需要估计提示文本自身的影响时，可额外在同一画像下比较基线与候选投影；不要把同时改变多项的结果称为单因素实验。
- 私有历史和实际请求只保存在忽略目录或临时目录。密钥从已有本机配置读取，不打印、复制进脚本或纳入 Skill。
- 用户允许开发中精简上下文时，可做单独的裁剪对照：保留理解当前问题所需的原始消息，先只改历史，再单独检查不相关画像/检索资料，记录前后哈希、长度和保留范围。原始证据不删除；开发授权不等于上线新的历史裁剪策略。精简后仍失败，不能把长历史说成已证实的根因。
- 使用隔离数据目录和本地工具副作用，不向真实聊天发送、不修改生产画像。真实模型付费调用和任何部署遵循当前授权；“看看效果”不意味着允许上线。

## 先分清失败，再调表达

从失败的具体 toolResult、拒绝参数和来源快照追溯，不用最终通用错误代替原因。区分模型参数、业务校验、预算耗尽、网络失败和回放适配错误。

回放必须忠实复现生产的消息 ID、角色、发言者、纠正状态、当前消息及来源绑定。先用实际失败参数做离线复现；不能为了让预览成功而省略权限或来源检查。若参数已被拒绝，接下来的模型修正也应纳入同一轮次数和费用；失败后的裸文本不是已放行的正式答复。

## 小步修改与实测

- 通用对话方式、模式长度、AI 个性分别放在各自合适的位置。一条规则尽量只维护一处；优先短的正向描述，删掉重复禁令、固定套话及针对测试原句的示例。
- 保留身份、权限、事实准确性和工具执行边界。不要增加正则语义分类、情绪打分、事后裁剪回复或额外“润色模型”来掩盖问题。
- 用少量真实失败对话验证，再用未参与措辞设计的不同内容检验迁移；选一个求助或专业问题检查是否过度变成短答。已有足够证据时不为凑数量扩大测试。
- 付费前确定样本及调用上界。每个结果独立保存，失败和效果不佳的回复一并展示；不要不停重抽直到出现满意回复。需要再次迭代时先说明新证据和实质不同的调整。

## 缓存、开销与审查

- 从 SDK 最终 HTTP payload 核对各阶段的 system/工具指纹、历史位置和增量追加。同阶段切换模式应保持固定前缀；工具续轮应保留上一请求后追加工具调用与结果。不要为了跨阶段相同而复制两套完整协议。
- 固定提示改版会更换前缀，首次冷缓存与每轮动态破坏前缀不同。布局稳定只能证明有利于复用，不能承诺供应商实际命中率。
- 比较提示字符/字节长度、相同输入的容量估算、实际模型调用次数和 usage。若 SDK 的 input 是未缓存输入，则真实输入为 input + cacheRead + cacheWrite，命中率为 cacheRead / 真实输入；核对供应商口径。输出单列，未知用量不记成零。
- 延迟用相同范围的模型调用比较并说明样本量和缓存条件；小样本或冷暖缓存不一致时不宣称性能提高。SDK cost 为零不代表免费。默认不增加整轮模型调用。
- 运行仓库已有的最窄构建/回归。只给真实确认的程序故障补必要测试，模拟答复不证明性格有效。
- 按任务要求或仓库约定做独立只读审查，提供实际 diff、原始目标、结果与最终 payload 证据；检查冗余、过拟合、身份边界、前缀及开销。

## PA 项目入口

在 PA checkout 中，优先按 `AGENTS.md`、`docs/profile-behavior.md`、`docs/context-cache.md` 和 `docs/logging.md` 定位。表达位于 `src/runtime.ts`、`src/turn-plan.ts`，AI 画像注入位于 `src/conversation.ts`；具体故障再读 `src/answer-grounding.ts`。先确认当前版本，不把这些路径当其他项目的约束。

`node scripts/repo-check.mjs --list` 可选择已有 scope。缓存检查使用实际本地 HTTP 请求；真实回放结果与原始聊天留在 `.local`。优先复用当前诊断读取入口，避免自建不完整的生产来源适配器。

交付时给出真实候选答复、仍未解决的问题、提示与调用开销变化、缓存检查结果，以及是否部署。手写理想示例应明确标注，不能冒充模型实测。
